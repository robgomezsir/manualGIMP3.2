É triste dizer, mas nenhuma versão do GIMP já lançada foi absolutamente perfeita. Mais triste ainda, provavelmente nenhuma versão jamais será. Apesar dos esforços para garantir que tudo funcione, um programa tão complexo como o GIMP está fadado a sofrer problemas de vez em quando, ou mesmo travar.

Mas o fato de erros serem inevitáveis não significa que eles devam ser aceitos passivamente. Se você encontrar um erro no GIMP, os desenvolvedores gostarão de saber sobre ele para que possam pelo menos tentar corrigi-lo.

Vamos supor, então, que você encontrou um erro, ou ao menos acha que encontrou: você tenta fazer algo, que gera como resultado algo que você não esperava. O que você deveria fazer? Como deveria relatá-lo?

Dica

O procedimento para fazer um requerimento de melhoria; isso é, para fazer um pedido aos desenvolvedores para adicionar uma funcionalidade ausente— é o mesmo procedimento para relatar um erro.

Assim como acontece em vários outros projetos de software livre, o GIMP usa um mecanismo de relatar erros chamado GitLab. Esse é um sistema baseado na web muito poderoso, capaz de gerenciar milhares de relatórios de erros sem perda de informação. Na verdade, o GIMP compartilha a sua base de dados do GitLab com todo o projeto Gnome.

1. Certificando-se de que é um Erro

A primeira coisa que você deverá fazer, antes de reportar o erro, é fazer um esforço para verificar que o que você está vendo realmente é um erro. É difícil descrever um método para fazer isso que seja aplicável em todas as situações, mas ler a documentação é útil, e discutir a questão no IRC ou Discourse pode ser muito útil. Se você estiver vendo um travamento, e não um comportamento imprevisto mais simples, as chances de ser um erro de verdade são grandes: programas bem-escritos não são desenvolvidos para travarem sob qualquer circunstância. De qualquer forma, se você fez o esforço para decidir se é realmente um erro, mas ainda sim não tem certeza, então vá em frente e relate-o: o pior que pode acontecer é gastar um pouco do tempo da equipe de desenvolvimento.

Nota

Aliás, existem algumas coisas que são conhecidas por causar travamentos no GIMP mas o trabalho de corrigi-las seria tão grande que não vale a pena. Uma delas é pedir ao GIMP para fazer algo que requer muita memória, como criar uma imagem de um milhão de pixels de cada lado.

Você também precisa verificar se está usando uma versão atualizada do GIMP: relatar um erro que já foi corrigido é uma perda de tempo para todos. (GIMP 1 não possui mais suporte, então se você usá-lo e encontrar erros, atualize para GIMP 2 ou viva com eles.) Inclusive, se você estiver usando uma versão de desenvolvimento do GIMP, certifique-se de que você pode ver o erro na última versão disponível antes de fazer o relato.

Se depois dessas considerações você ainda acreditar que tem um legitimo relatório de erro ou pedido de melhoria, então o próximo passo é ir para a lista de problemas do GIMP (https://gitlab.gnome.org/GNOME/gimp/issues/), e tentar ver se mais alguém já relatou a mesma coisa.

1.1. Encontrar um erro em específico

Informe alguns termos de busca (separados por espaço), como por exemplo

filter crash

, na caixa de texto "Buscar ou filtrar resultados..." e aperte Enter. Por padrão, você verá apenas relatórios em aberto; você pode mudar isto clicando em "Tudo" acima do campo de busca.

O resultado é ou uma lista de relatórios de erros – tomara que não muito longa – ou uma mensagem dizendo “Desculpe, seu filtro não encontrou resultados”. Se você não encontrar um relatório de erros relacionado ao fazer isso, pode valer a pena tentar outra busca com termos distintos. Se, apesar dos seus melhores esforços, você submeter um relatório de erro e ele terminar encerrado como uma duplicata, não se chateie: isto aconteceu repetidamente ao autor desta documentação.
